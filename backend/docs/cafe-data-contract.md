# 행궁동 카페·메뉴 데이터 출처와 입력 기준

관련 작업: [Issue #21](https://github.com/seoJing/opensourceSW/issues/21) · 조사일: 2026-11-18 · 상태: 수집 결과 기록, 맛 기반 MVP 방향 반영·속성 상세 검토 전

## 확보한 자료

| 단계 | 출처와 확인한 값 | 범위 |
| --- | --- | --- |
| 매장 탐색 | NAVER API HUB 지역 검색 126회: 상호·주소·업종·좌표·연결 URL | 중복 제거한 후보 152건. 카페 전체 명부가 아님 |
| 매장 대조 | 네이버 지도 검색 목록: Place ID·주소·업종·좌표 | 행궁동의 12개 법정동 주소와 카페 관련 업종으로 걸러 321곳 발견 |
| 메뉴 확인 | 각 매장의 공개 지도 메뉴 페이지: 메뉴 ID·이름·설명·표시 가격·일부 옵션 | 321곳 확인. 272곳에서 구조화 메뉴 5,020건 추출, 49곳에서는 해당 형식의 메뉴를 찾지 못함 |
| 내부 입력 | 원문을 검토해 UTF-8 JSON으로 변환 | 카페 320곳·메뉴 5,011건 로딩, 메뉴 9건 보류. 도로명주소가 없는 매장 1곳은 입력 보류 |

행궁동 범위는 [수원시 팔달구 행궁동 안내](https://paldal.suwon.go.kr/submain_view.asp?TopID=sub06&menuid=sub0604)에 나온 12개 법정동을 기준으로 잡았습니다. 발견한 매장을 모두 확인했지만, 검색 결과 밖의 업소까지 빠짐없이 찾았다는 뜻은 아닙니다.

**공식 지역 검색 API에는 메뉴명·가격·방문자 리뷰 본문이 없습니다.** 메뉴는 발급받은 API의 응답이 아니라 일반 브라우저에 표시되는 네이버 지도 메뉴 페이지의 구조화된 항목에서 확인했습니다. Place ID에 연결된 상세 정보의 메뉴 참조만 읽고 다른 매장의 항목을 혼합하지 않았습니다. 조회 중 방문자 리뷰 본문과 평점은 수집 대상에서 제외했습니다. 메뉴 원문 추출은 실행한 일회성 배치이며, 서버의 정기 수집 기능이 아닙니다.

사용자가 사전 허락을 확인한 비배포 학습 MVP 검토 범위에서 조사했습니다. 검색 API 응답과 지도 메뉴 페이지는 서로 다른 공급 경로입니다. 이번 검토 결과만으로 외부 공개 배포나 운영 서비스에 원문 데이터를 사용할 범위까지 확정하지 않으며, 팀이 공유할 자료와 사용 범위는 별도로 결정해야 합니다.

## 파일과 출처 추적

검토용 데이터 버전은 `haenggung-2026-11-18.2`입니다. 사용자 PC의 `~/.local/share/opensourceSW/catalog/haenggung-2026-11-18.2/`에 다음 파일을 보관합니다.

| 파일 | 내용 |
| --- | --- |
| `catalog.json` | 카페·메뉴 목록, 내부 ID, 가격·판매 상태, 항목별 출처 URL·원자료 ID·조회일 |
| `collection-registry.json` | 메뉴를 찾지 못한 곳을 포함한 발견 매장 321곳의 처리 상태 |
| `review-decisions.json` | 원문 5,020건마다 로딩·보류 판단과 이유, 표시 가격·옵션 원문 |
| `manifest.json` | 버전, 수량, 상태별 집계, 카탈로그 SHA-256 |
| `source-evidence.json`, `search-source-evidence.json` | 매장별 메뉴 자료와 검색 목록의 파일 경로·SHA-256 |

이 파일들은 저장소 밖의 **로컬 검토 자료**입니다. 저장소의 예시 JSON과 혼동하거나 팀원이 자동으로 받을 수 있는 자료로 간주하지 않습니다. 전달 묶음과 해시 검증은 PR #28, Docker 적재 원본 연결은 PR #30에 정리했습니다. 실제 공유 매체와 갱신 주기는 실행 환경에 맞게 정합니다. 비밀키·세션·비밀번호는 카탈로그에 넣지 않습니다.

## 내부 입력 기준

[Issue #22](https://github.com/seoJing/opensourceSW/issues/22)의 카탈로그 입력은 `schemaVersion=1`, 별도의 `dataVersion`, `cafes[]`, `menus[]`로 구성합니다. 카페는 내부 ID·상호·도로명주소·좌표(미확인 시 null)·출처를 가집니다. 메뉴는 내부 ID·카페 ID·이름·설명·원화 가격·`isDemo`·판매 상태·출처를 가집니다. 출처의 `observedOn`은 **페이지 조회일**이며 판매 확인일이 아닙니다. 메뉴 ID는 Place ID와 원문 메뉴 ID를 함께 사용해 생성했고, 공급자의 원문 ID가 장기간 안정적인지는 검증하지 않았습니다.

고정 표시 가격만 원화 정수로 옮겼습니다. 가격 변동·범위·미표기 메뉴 227건은 `priceKrw=null`로 두고 원문 표시를 검토 자료에 보존했습니다. 무료로 표시된 안내성 항목 등 9건은 실제 0원 상품인지 구분할 수 없어 보류했습니다. 메뉴명·설명에 시즌 종료가 명시된 40건은 `SEASON_ENDED`, 판매 확인 근거가 없는 나머지 4,971건은 `UNKNOWN`입니다. 로더 통과와 현재 판매 여부 확인은 다른 판단입니다.

일부 원문에는 옵션이 있지만 카탈로그 v1에는 옵션·재료·알레르기·맛 점수·분위기 점수 필드가 없습니다. 옵션 원문은 검토 파일에 보존하고, 없는 속성을 0점이나 `미지원`으로 채우지 않습니다. 메뉴가 아닌 선물·공지 항목과 주류 가능 항목도 남아 있으므로, **5,011건 전체를 추천 후보로 확정한 것은 아닙니다.**

## MVP 취향 속성 재정리

사용자 요청에 따라 맛 3축 고정과 로컬 모델 실험을 철회했습니다. 전체 속성 후보를 먼저 보고 이번 시연에 필요한 항목만 선택합니다. 카페·메뉴의 수집 자료는 유지합니다. 새 모델·대량 수치화는 속성 범위 선택 뒤 검토합니다.

MVP에서는 메뉴 종류·맛 계열·맛 강도·식감·대체유·카페인·가격·공간 등 기존 설문의 후보를 살펴봅니다. 모든 후보를 구현하지 않으며, 원자료에 없는 값을 0~1로 채우지 않습니다. 먼저 최소 속성 객체를 정하고 질문과 선택지를 맞춥니다. 가격·공간의 포함 여부도 전체 후보를 보고 정하며 이전의 맛 전용 계획을 확정 계약으로 사용하지 않습니다.

설명은 전체 후보와 데이터 유무를 확인하는 수준으로 유지합니다. 세밀한 속성 관리 엔진이나 관리자·자동 학습 기능은 만들지 않습니다. 추천 응답과 화면 연동은 MVP 속성을 정한 뒤 진행합니다.

[Issue #20](https://github.com/seoJing/opensourceSW/issues/20)의 설문 정의 조회, [Issue #24](https://github.com/seoJing/opensourceSW/issues/24)의 PostgreSQL 적재·조회(PR #31)는 추천 점수 계산과 별개입니다. 이번 문서는 DB 테이블이나 새로운 프론트 API를 정의하지 않습니다.

## 검증 범위

아래는 DB 전환 전 조사 단계의 검증 기록이며 현재 PR 전체의 테스트 수가 아닙니다. 당시 로컬 백엔드 테스트 167개와 인증 PR #19 코드를 합친 별도 검증용 복사본의 테스트 214개가 통과했습니다. 외부 JSON을 활성화한 검증용 Spring Boot 서버에서 카페 320곳·메뉴 5,011건이 파일과 정확히 일치하고 HTTP 점검 8건이 통과했습니다. 검증 DB는 H2이며, Docker Compose와 PostgreSQL을 통한 실제 데이터 기동은 이번 검증 범위에 포함되지 않았습니다.


## 현재 저장·조회 기준

카페·메뉴의 실행 중 조회 저장소는 PostgreSQL입니다. `catalog.json`은 최초 적재·버전 교체·다른 PC 재현에 사용하는 전달 원본입니다. PR #23의 로더는 파싱·입력 검증을 담당하고, PR #31은 트랜잭션 적재와 DB 조회를 담당합니다. 전체 `Catalog`를 메모리 Bean으로 유지하는 기존 시작 로딩 초안은 PR #31에서 교체했습니다.

2026-11-18 PR #31의 `6598cae`에서 일반 테스트 110개와 실제 PostgreSQL 테스트 14개를 통과했습니다. 실제 카페 320곳·메뉴 5,011건을 DB에 적재해 원본 전체 필드·해시를 대조했고, JSON 마운트 없이 컨테이너를 재생성한 뒤에도 named volume에 자료가 유지되는 것을 확인했습니다. 이 결과는 인증·설문까지의 전체 통합 완료를 의미하지 않습니다.
