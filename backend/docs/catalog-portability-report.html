평가 항목별 확인

항목지금 확인한 사실판정과 남은 증거
Git 브랜치·PRIssue별 브랜치에서 #19 인증, #23 카탈로그, #25 출처 문서, #26 설문, #28 전달 기준, #30 Compose 연결을 main 대상으로 올렸어요. #24는 선행 #23 위의 별도 브랜치로 푸시했어요.리뷰·병합 대기 병합 이력과 최소 1명 리뷰가 최종 증거예요.
Docker·KubernetesCompose에 frontend, backend, db 세 서비스가 있어요. 프론트의 /api/health는 백엔드로, 백엔드는 PostgreSQL로 연결하고 postgres_data named volume이 있어요.기본 구성 충족 볼륨은 DB 파일용이며 카탈로그 JSON 적재 근거는 아니에요. Kubernetes 구성은 없어요.
추가 오픈소스백엔드 PR에는 Spring Security와 Jackson 사용 이력이 있어요. 프론트 런타임에는 Nginx가 있어요.수업 목록 대조 필요 수업에서 배운 오픈소스 목록을 확인해야 평가 인정 여부를 말할 수 있어요.
GitHub Actions저장소에 Frontend Lint/Test, Backend Test, Docker Build, Compose Smoke Test, Repository Checks, PR Coordination의 7개 워크플로가 있어요.검사 7개 통과 PR #25와 #26의 현재 커밋에서 모두 통과했어요. 각 PR의 Actions 기록이 증거예요.

지금 실행하면 데이터는 어디로 가나요?

경로현재 동작
catalog.json → CatalogLoader → Catalog Bean#24 브랜치에서 명시적으로 활성화하면 시작 시 JSON을 읽어 메모리에 보관해요. 파일이 없거나 형식이 틀리면 시작을 거부해요.
Catalog → PostgreSQL미구현 카페·메뉴 테이블과 INSERT·마이그레이션이 없어요.
Docker Compose → catalog.jsonDraft PR #30 선택형 읽기 전용 연결을 준비했어요. 현재 main에는 없고 실제 컨테이너 실행도 미검증이에요.
frontend → /api/v1미구현 Nginx는 현재 /api/health만 백엔드로 연결해요. 기능 API 경유는 별도 프록시 설정과 브라우저 검증이 필요해요.
postgres_dataPostgreSQL의 저장 파일을 유지해요. JSON을 DB로 옮기는 동작은 하지 않아요.

팀 전달 파일 검증 결과

팀 내부 공유용 묶음은 catalog.json, manifest.json, SHA256SUMS로 구성했어요. 압축 크기는 약 364KB예요. 압축을 다른 로컬 폴더에 풀어 두 파일의 해시와 manifest의 버전·수량을 검사했어요.

검사실제 결과
sha256sum -c SHA256SUMS통과 catalog·manifest 모두 일치
manifest 대조통과 버전 haenggung-2026-11-18.2, 카페 320곳, 메뉴 5,011건, catalog SHA-256 일치
Java 로더통과 추출된 파일에서 카페 320곳·메뉴 5,011건 로딩
다른 경로의 Compose 설정통과 일반 경로와 공백·한글이 있는 경로의 읽기 전용 연결, 필수 변수 누락 오류를 확인했어요. 컨테이너 경로는 /app/data/catalog.json으로 같아요.
실제 카탈로그 Docker 기동미검증 로컬 Docker daemon이 없어 실행 결과는 확인하지 못했어요. 다른 사용자 PC 접근은 이번 작업의 필수 조건이 아니에요.

추천용 메뉴 기준

5,011건 중 40건은 시즌 종료, 4,971건은 판매 여부 미확인이에요. 판매 확정 메뉴는 현재 0건이에요. 메뉴 227건의 가격과 2,275건의 설명이 비어 있어요.

  1. 시연 자료, 판매 불가·시즌 종료 메뉴와 안내·선물·주류 같은 비추천 항목을 제외해요.
  2. 나머지는 검토 대상으로 두고, 음료·디저트·베이커리 분류와 근거를 기록해요. 분류가 불명확하면 추천하지 않아요.
  3. 가격 미확인 메뉴는 가격 순위 계산에서 제외해요. 맛·재료·옵션은 원문 근거가 있을 때만 사용해요.
  4. 판매 여부가 UNKNOWN인 메뉴를 시연 추천에 쓰면 화면에서 확인 필요 상태를 표시해요.

다른 사용자가 실행할 때

  1. 선행 PR #19·#23을 리뷰·병합하고 #20·#24의 최신 main 재검증을 마쳐요.
  2. 버전 묶음을 원하는 경로에 풀고 압축 파일 해시, 파일별 해시와 manifest를 확인해요.
  3. Docker와 Compose를 준비하고 CATALOG_FILE에 자신의 파일 경로를 설정해요. PR #30 실행 안내에 Windows·WSL·Linux·macOS 절차가 있어요.
  4. 확장 Compose로 실행해 세 서비스 health와 카탈로그 로딩 로그를 확인해요. 파일 경로를 바꾸면 백엔드를 다시 생성해야 새 연결이 반영돼요.

이 보고서는 2026-11-18의 검증 스냅샷이에요. 실행 설정·안내 준비와 실제 환경의 동작 검증을 구분해 기록했어요. 프론트 기능 API 프록시와 DB 적재는 별도 작업이에요.
