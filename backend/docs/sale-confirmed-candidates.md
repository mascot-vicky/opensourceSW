# 추천 후보의 판매 확인 기준

메뉴 검토자가 음식·음료로 확인한 메뉴 ID와 그 카탈로그 버전을
`SaleConfirmedMenuRepository.findConfirmedIds`에 전달한다. 조회에는 #31의 카탈로그 테이블이 필요하다.

활성 버전과 검토 버전이 일치해야 한다. 시연용 메뉴는 제외하고,
`AVAILABLE` 상태에 확인일(당일 또는 과거)과 비어 있지 않은 확인 근거가 있는 메뉴 ID만
카탈로그 순서대로 반환한다. 확인일은 매장 등의 판매 확인 기록에 근거한다.
원천 페이지를 조회한 날짜로 대체하지 않는다.

고정 데이터 `haenggung-2026-11-18.2`에는 미확인 4,971건, 시즌 종료 40건이 있어
5,011건 전체를 입력해도 결과는 빈 목록이다. 후보를 확보하려면 실제 판매 근거를 기록하고
새 데이터 버전으로 적재한 뒤 그 버전의 메뉴를 검토한다.
빈 결과를 미확인 메뉴로 채우지 않는다. PR #26의 HTTP 계층은 아래 조회 결과를 카드 한 장으로 전달한다.

## 추천 순위

`SaleConfirmedMenuRepository.rank`는 검토한 데이터 버전·음식/음료 메뉴 ID, 이번 요청의 제외 ID, 저장 답변에서 만든 `PreferenceProfile`을 받는다.
활성 버전에 속하고 판매 근거를 갖춘 후보만 정렬한다. 제외 ID는 재추천하지 않는다.

| 비교 대상 | 일치 조건 |
|---|---|
| 종류·가격대·단맛 | 사용자가 고른 값과 검토된 메뉴값이 같음 |
| 커피 기반 | 음료 선호일 때 커피/비커피 선택과 메뉴값이 같음 |
| 제공 온도 | 선택한 온도를 제공함. 양쪽 모두 제공하는 메뉴도 1점 |
| 시그니처 | 확인된 시그니처/일반 여부가 사용자 선택과 같음 |

각 일치는 1점이며 점수 범위는 0~6이다. 무선호·미확인은 일치 수에 포함하지 않는다.
일치 수 내림차순, 동점이면 카탈로그 등록 순서(`ordinal`) 오름차순으로 반환한다.
모든 답을 건너뛰면 모든 후보가 동점이다. 판매 확인 후보가 없으면 빈 목록이다.
이 순위는 백엔드 내부 결과이며 프론트에서 별도 점수를 계산할 필요가 없다.

## 카드 조회에 사용할 검토 목록

팀의 음식·음료 검토표에서 INCLUDE로 확정한 같은 버전의 메뉴 ID만 사용한다.
Compose를 실행하는 셸에서 `REVIEWED_CATALOG_VERSION`을 검토표의 버전으로,
`REVIEWED_MENU_IDS`를 쉼표로 구분한 ID로 설정한다. 두 값은 백엔드 설정이며
브라우저 요청에는 포함하지 않는다. 고정본의 기본 목록은 비어 있다.
검토 ID를 지정해도 DB의 판매 상태·확인일·근거를 모두 통과해야 한다.
카탈로그가 이미 적재됐지만 현 버전의 검토 목록이 없거나 모두 제외됐다면 후보는 0건이다.
활성 카탈로그가 없거나 DB 조회가 실패하면 서비스 오류를 반환한다.

카드 조회는 동일한 DB 스냅샷에서 순위 첫 행과 메뉴·매장을 읽는다.
길찾기는 프론트 시연에서 사용하던 네이버 지도 도보 경로 형식을 따른다.
좌표가 없거나 웹 지도 투영 범위를 벗어나면 길찾기 URL은 null이다.
